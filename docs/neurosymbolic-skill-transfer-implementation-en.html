01 · Transfer object

We transfer intervention-grounded program content, not game actions

A skill is implemented as typed operators, transition or partial-order constraints, terminal relations, and an abstention contract supported by source interventions. Source action names, pixels, game identity, and the complete source controller are not transfer objects.

Most accurate method name: intervention-grounded symbolic program transfer with target-native neural grounding.

The source supplies

Causal structure

Matched intervention forks identify effect relations, control flow, stopping conditions, and evidence-sensitive abstention.

The target supplies

Native grounding

Target text, images, frames, or candidate actions are bound to entities, relations, effects, and calibrated confidence.

The Harness supplies

Safe composition

It authorizes only a unique structural match with qualified grounding and positive prior utility; otherwise it falls back.

Transferred invariants

  • operator type and effect relation
  • transition, recurrence, or composition
  • terminal predicate
  • unique-candidate and abstention rules
  • source receipt lineage
≠

Not transferred directly

  • source pixels or visual features
  • source action tokens or game identity
  • a complete target policy
  • target reward, gold answer, or formal success
  • one hand-written universal controller

02 · End-to-end architecture

Six deliberately separated authorities

The central implementation choice is not merely connecting modules; it is limiting what each module may observe and emit.

1 · Source receipts Real intervention tuples, effects, next states, and lineage hashes
2 · Program induction Find a unique explanation in a typed hypothesis space
3 · Anonymous IR Operators, transitions, terminals, and abstention
4 · Target grounder Bind only target-native entities, effects, and confidence
5 · Authorization Structure × qualification × past utility
6 · Native executor The only component allowed to emit an action or answer 
source data authority       = source observations + interventions only
induction authority         = emit a program, never a target action
target grounding authority  = bind native evidence, never read formal outcome
selection authority         = emit SELECT_SKILL / ABSTAIN, never an action
execution authority         = emit a native action after valid authorization
evaluation authority        = open gold/outcome only after receipts are frozen

03 · Source-side implementation

From rollout to a source-qualified symbolic program

  1. Instrument source environments. At each step, record the before state, native candidates, selected intervention, after state, reward or terminal evidence, operational effect, and content hash.
  2. Build matched candidate forks. Execute different candidates from the same source state and retain successful and failed forks. Success-only trajectories cannot identify a causal operator.
  3. Anonymize source vocabulary. Action names, game names, and semantic labels cannot cross into the target. The inducer reads typed state/effect endpoints and transition evidence.
  4. Search a frozen hypothesis class. Find the unique operator, transition, terminal, and abstention program that exactly separates intervention outcomes. Zero or multiple explanations both cause abstention.
  5. Qualify on source evidence. Test held-out episodes and fresh reserves, plus shuffled effects, permuted transitions, alpha-renamed actions, and missing-evidence controls.

04 · Shared symbolic representation

The shared object is an IR contract, not a canonical controller

Different games may induce different program bodies, but each body is wrapped in the same content-addressed envelope. Target routing operates on required capabilities and program content, never source identity.

Neural-symbolic program contract

Program = {
  typed_operators,
  transition_or_partial_order,
  terminal_predicates,
  abstention_rules,
  neural_probe_specs: {
    input_kind,
    model_artifact_sha256,
    supported_min_score,
    refuted_max_score,
    UNKNOWN band
  },
  source_lineage,
  program_sha256
}

Hard symbolic checks

  • type and capability compatibility
  • program and artifact hash consistency
  • candidate uniqueness
  • reachable transitions and explicit termination
  • UNKNOWN always fails closed

Neural probe contract

  • return only a calibrated score or binding
  • never write control flow
  • never observe source identity
  • never observe formal outcome or gold
  • freeze artifact and thresholds

Content-addressed evidence

  • program, grounder, and executor have hashes
  • authorization is bound to target state
  • evaluation opens after runtime receipts
  • alpha renaming cannot change execution

  • structural_ir_applicability.py — source contract / target requirement matching.

05 · Target-native neural grounding

Only the grounder and executor change across targets

The target grounder turns text, images, or video evidence into the target-native bindings required by the IR. The symbolic program never reads pixels, native action names, or gold. Grounder training is restricted to development or adaptation splits, and thresholds are frozen before qualification.

06 · Selection, authorization, execution

The unified Harness decision path

eligible_programs = source_programs where:
  source_intervention_qualified
  and learned_from_(state, action, effect, next_state)
  and target_data_read == false
  and named_policy_template_used == false

selected = unique_structural_match(eligible_programs, target_requirement)

if no unique selected program:
    return ABSTAIN
if target_grounder not qualified or structural predicates not closed:
    return ABSTAIN
if past matched utility <= 0 or authentic does not beat permuted control:
    return ABSTAIN

authorization = SELECT_SKILL(program_sha256, executor_sha256)
native_output = target_native_executor(authorization, grounding, candidates)
No current-task outcome feedback: the current task's reward, gold answer, or official success cannot influence its own route selection. Utility calibration may use only earlier completed, frozen matched trials.

The Harness may emit

  • SELECT_SKILL or ABSTAIN
  • selected program hash
  • target executor identity and hash
  • utility and authenticity lower bounds
  • a structured reason and authorization receipt

Only the executor may emit

  • a WebShop native action
  • an ALFWorld command
  • a DiscoveryWorld operation
  • a TIR or video answer slot
  • a MiniGrid anonymous recovery token
  • src/motif_transfer/unified_transfer_runtime.py — route validation, utility/authenticity gates, and authorization.
  • unified_neurosymbolic_harness.py — structural selection and target-execution handoff.

07 · Adding a new target domain

Standard procedure for a new target adapter

A new domain must begin with a target MDP or QA interface and measurable native grounding—not by inserting source prompts into a target actor.

  1. Write the target interface contract. Define observation, native candidates, formal outcome, interaction budget, and information that runtime may never read.
  2. Define the IR requirement. List target-groundable capabilities, typed entities/effects, and terminal relation without source game names or action mappings.
  3. Build the target-native grounder. Train or tune prompts only on development/adaptation tasks; record model, data, threshold, and artifact hash.
  4. Run intrinsic qualification. On fresh qualification, measure coverage, covered accuracy, calibration, unique binding, and abstention. A failure keeps formal reserve sealed.
  5. Implement the native executor. Its only inputs are authorization, grounding receipt, and native candidates; verify it accepts no source token or gold.
  6. Freeze the matched condition matrix. Include neural-only, source-induced, source-permuted/shuffled, generic scaffold, and target-written isomorphic ceiling.
  7. Run untouched formal evaluation. Atomically write runtime receipts before opening the evaluator; report paired wins/losses/ties and negative-transfer rate at the correct clustering unit.
  8. Register the route. Add program, grounder, executor, and evidence-report hashes to the skill library only after every gate passes.
Formal gates that must be preregistered
  • Target selection and splits freeze before outcome calls.
  • Source induction reads zero target trajectories or outcomes.
  • Target grounder qualification precedes formal reserve.
  • Every unauthorized row preserves the identical baseline fallback.
  • Authentic content significantly beats destructive source controls.
  • Negative transfer remains under a frozen limit.
  • Alpha renaming is invariant and source identity is hidden.
  • A target-written equivalent acts as the content-versus-provenance ceiling.

The fresh reserve reached 2,246/2,246. See the Harness 9B six-benchmark V3 report.

Frozen Harness 9B V3 supervision contract

input:
  anonymous seven-program source catalog
  target-native typed structural requirement
  source intervention qualification flags

targets:
  SELECT_SKILL + copied opaque catalog ID
  or fail-closed ABSTAIN + structural reason

controls:
  catalog order and opaque alias permutations
  duplicate match / unqualified source
  IR kind / operator / recurrence / terminal mismatch

split:
  source-only closure train/validation
  old source retention + fresh alias held-out
  no target prompt, error ID, action, or outcome in SFT
  1. Done: seal the consumed diagnostic. V2 scored 2,238/2,246; none of the eight target errors became training rows.
  2. Done: freeze a fresh reserve first. Prompts, aliases, catalog orders, and IDs are disjoint from V1; native tasks retain their original pre-outcome authority.
  3. Done: source-only permutation closure. Seven source programs are treated symmetrically, with 3,584 SELECT and 3,584 ABSTAIN rows.
  4. Done: re-pass source gates. Scalar decision accuracy is 100%; the 2,016-row multi-IR exact score is 99.90%.
  5. Done: six-benchmark strong substitution closure. 2,246/2,246 routes and 1,864/1,864 actions match; base route exact is 0%.
  6. Optional next: target-adapted Harness. A separate five-target-domain SFT adapter may estimate a deployment ceiling, but cannot replace source-only transfer evidence.
