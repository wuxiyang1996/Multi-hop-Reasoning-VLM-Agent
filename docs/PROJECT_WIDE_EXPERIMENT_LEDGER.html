问题演化

  1. 阶段 0：旧系统与 co-evolution。 原 repo 已经有 harness/crafter/orchestrator、skill bank lifecycle、SFT/GRPO、Qwen3.5-9B/35B stack， 并在游戏上有可运行 skill/context/LoRA 路线。
  2. 阶段 1：Layer-C / mega-skill / reasoning plan。 406 skills 被 LLM lifted 成 PERCEIVE/DECIDE/COMMIT/VERIFY 等计划，跨域 signature 覆盖率看起来很高。 后续审计发现它更像自然语言/LLM prior，不是可执行 receipt-grounded transfer proof。
  3. 阶段 2：principled skill transfer。 尝试用 typed effect、one-shot admission、source-only SFT 和 ALFWorld official success，避免 COLLECT→TAKE 等手写映射。 这条线工程上跑通，但 v1 Harness 过度收缩 action scope，导致 0/59。
  4. 阶段 3：agent-native harness v2/v3。 改成 Agent 只提出 target-native candidates，Harness 只验证 receipt/admissibility/official outcome； 35B smoke 和 dev pilots 能跑，但 source-conditioned treatment 没有超过 target-only。
  5. 阶段 4：receipt-grounded causal motif。 旧 mega-skill 被降为 LINEAGE_RETRIEVAL_ONLY；统一 event protocol 不再叫 skill。 真实 motif 必须有 proposal/execute/observe/update、replay fork、source attribution 和 target incremental value。
  6. 阶段 5：two-agent clean。 repo 清成 Decision Agent + Motif/Harness Agent；旧 exact topology 失败后，主对象降为 weak receipt-grounded knowledge。
  7. 阶段 6：当前结论。 ALFWorld weak-prior canonical pilot 的 task-0 正例经 10-seed frozen replication 未复现； 所以现在暂停 positive transfer 主张，转向 target-adapted prediction Harness gate。

这条对话里已经定下的决定

决定原因落地位置
不再主张 skill transfer reviewer 会把 skill 理解成可复用 policy/action program；当前证据只支持更弱的 test-time reasoning benefit 问题。 clean README、TEST_TIME_RECEIPT_GROUNDED_KNOWLEDGE.md、EXPERIMENT_LEDGER.html
Harness 无 target action authority 否则 source prior 会变成手写/模型生成 target policy，无法归因。 two-agent architecture docs and runtime。
旧 mega-skill 仅 lineage 180 members / 20 families / 14 signatures 显示 collapse；无 executable control-flow receipts。 causal motif audit、clean docs。
不继续 task-0 20-seed 扩展 10-seed frozen replication 已显示 authentic 不优于 generic；更多同机制样本只会精确估计近零效应。 ALFWorld weak-knowledge pilot doc。
不释放当前 Harness LoRA job strong teacher mechanism 尚未证明；用小模型训练会掩盖机制失败。 target rollout collection / implementation status。
暂停此线，先 fire 两个 video projects 这条线已进入高风险方法论阶段；video projects 更 promising，资源优先给更清晰闭环。 本页和 thread close-out。

离开 thread 后的接力棒：当前不是“失败项目”，而是一个高风险、需要强 gate 的方法线。 可恢复点是 clean repo 的两个网页账本和 docs/results；不要从旧 prompt 调参继续，而要从 prediction Harness gate 重新开。

如果之后重启：最小 Gate

  1. 先做 target-adapted large Harness。 用 GPT-5-mini 或更强 teacher，在 ALFWorld 或 video target 上做 action/proposal-conditional future progress prediction，k 固定为 0/1/2/4/8。
  2. 补 target data 形态。 现有 ALFWorld adaptation trace 多为单 proposal，不能支撑 action-value ranking； 需要 multi-proposal 或 matched continuation receipts。
  3. 先看 prediction curve，不先上线控制。 如果 target-only/target-adapted predictor 自己不随 k 改善，就先修 receipt/schema/data，不谈 source。
  4. 再加 source 条件。 比较 large generic、target-adapted、source-only、source+target、shuffled+target。 只有 source+target 曲线相对 target-adapted 稳定左移，才有 source-derived benefit。
  5. 最后才 distill。 只蒸馏 future-receipt-verified prediction/ranking/source-off 样本，不蒸馏 CoT 或 target action。
如果失败解释下一步
large target-adapted predictor 不工作target receipts 或 prediction schema 不够。回去补 proposal sets / horizon labels。
target-adapted 有效，source 无增量快速适应可行，但不是 source transfer。改成 target-trained adaptive Harness。
prediction 有效，online decision 无效控制接口出问题。修 ADMIT/REPLAN/ABSTAIN 与 fallback budget。
authentic 输给 generic/shuffledsource content 无归因价值或有负迁移。报告 negative transfer/source-off latency，停止 positive source claim。
